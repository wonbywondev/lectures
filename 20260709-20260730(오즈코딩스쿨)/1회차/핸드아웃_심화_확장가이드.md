## 1. CLI 위임 넓히기 — "이것도 CLI로 되나?"

오늘 배운 "말 한마디로 맡기기"는 다른 도구에도 그대로 통합니다. **`login`(브라우저 인증)만 사람이 하고 나머지는 전부 AI에게.**

새 도구를 만날 때 공식:
> 구글에 `툴명 + cli` 검색 → 공식 문서 링크를 AI에게 주고 *"이거 보고 설치해줘"*

혼자 연습해볼 만한 CLI들 (오늘 방식 그대로):

| 도구 | 한 줄 체험 | 이렇게 말해보세요 |
|------|-----------|-------------------|
| **GitHub CLI (`gh`)** | 내 코드를 온라인에 백업 | `gh auth login` 후 → *"gh로 레포 만들어서 지금 프로젝트 올려줘"* |
| **npm / npx** | 패키지 설치·실행 | *"필요한 패키지 설치하고 실행해줘"* |
| **로컬 서버 띄우기** | 만든 페이지를 브라우저로 확인 | *"이 폴더를 로컬 서버로 띄워서 열어줘"* |

> 💡 "이 도구 CLI 있어?"를 **AI에게 먼저 물어보는 습관**을 들이면, 웬만한 건 말로 다 됩니다.

## 2. git 더 능숙하게 — 오늘 배운 커밋/롤백/태그를 손에 붙이기

오늘 개념은 배웠으니, **몸에 익도록 반복**하는 게 핵심이에요.

- **커밋 메시지를 의미 있게** — "커밋해줘"만 하지 말고 뭘 했는지 남기기.
  ```
  "로그인 버튼 추가" 메시지로 커밋해줘
  ```
- **자주, 작게 커밋** — 큰 작업 하나로 몰지 말고 단계마다. 되돌릴 지점이 촘촘할수록 안전.
- **지금까지 뭘 했는지 보기** — 내 세이브포인트 목록 확인.
  ```
  지금까지 커밋 목록 보여줘
  ```
- **태그를 나만의 이정표로** — `여기까지-잘됨`, `배포직전` 같은 이름으로 안전지대 표시.
  ```
  지금 상태에 "잘되는버전" 태그 붙여줘
  ```

### 브랜치 — 갈라서 안전하게 실험하기

**브랜치(branch)**는 지금 잘 되는 코드는 그대로 두고, **옆에 복사본을 만들어 거기서 마음껏 실험**하는 거예요. 실패해도 원래 코드(main)는 멀쩡합니다.

- **새 기능은 브랜치에서** — 본줄을 건드리지 않고 시도.
  ```
  "다크모드" 브랜치 만들어서 거기서 작업해줘
  ```
- **잘 되면 합치기(merge)** — 실험이 성공하면 본줄에 반영.
  ```
  다크모드 브랜치 잘 되니까 main에 합쳐줘
  ```
- **망하면 버리기** — 실패한 실험은 브랜치째 삭제, 본줄은 무사.
  ```
  다크모드 브랜치 별로니까 지우고 main으로 돌아가줘
  ```
- **지금 어느 갈래인지 확인**
  ```
  지금 어떤 브랜치에 있는지, 브랜치 목록 보여줘
  ```

> 💡 **커밋/태그 vs 브랜치:** 커밋·태그가 "시간축으로 되돌리기"라면, 브랜치는 "**여러 갈래로 나눠 동시에 실험**"이에요. 큰 기능 붙일 때 특히 유용합니다.

> 🎯 오늘 실습을 **집에서 2~3번만 반복**하면 커밋·되돌리기가 손에 붙어요. 그게 다음 회차의 든든한 기반이 됩니다.

## 3. context7 200% 활용

- **두 가지 사용법**
  - `npx ctx7@latest` — 회원가입·키 없이 바로 (오늘 방식). 사람 많으면 느릴 수 있음.
  - **MCP 연결** — Claude에 상시 붙여두면 매번 "context7으로" 안 붙여도 자동 활용.
    ```
    context7을 MCP로 연결해줘
    ```
- **rate limit(속도 제한) 풀기** — 자주 쓴다면 [context7.com/dashboard](https://context7.com/dashboard)에서 **무료 키** 발급 → 등록하면 속도·한도 안정적.
- **진가가 나오는 순간** — 설치 절차보다 **라이브러리 최신 문법·새로 생긴 기능**에서 강력.
  - AI가 옛날 방식으로 짤 때 → *"context7으로 최신 방식 확인해서 다시 짜줘"*
  - 새 라이브러리 쓸 때 → *"context7으로 이 라이브러리 최신 사용법 알려줘"*

## 4. AI에게 잘 맡기는 법 (모든 회차에 통하는 태도)

도구보다 중요한 건 **AI를 부리는 감각**이에요. 오늘부터 연습해두면 좋아요.

- **큰 걸 한 번에 시키지 말고 쪼개서** — "사이트 만들어줘"(X) → "먼저 소개 페이지부터 만들어줘"(O).
- **매 단계 커밋** — 잘 되는 지점을 남겨야 실패해도 돌아올 수 있어요.
- **결과를 검수** — AI가 만든 걸 그대로 믿지 말고 **실행해서 눈으로 확인**. 우리는 시키고 검수하는 **PM**.
- **방향이 틀리면 빨리 멈추기** — AI는 빠른 만큼, 방향이 1도만 틀어져도 크게 어긋나요. 이상하면 바로 되돌리기(그래서 git!).
