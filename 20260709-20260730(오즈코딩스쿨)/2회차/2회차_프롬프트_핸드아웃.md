## 📍 오늘의 목적지

> **큰 목적지** — 4주 뒤, 여러분이 프롬프트만으로 만드는 **내 미니당근**
> **오늘의 도착점** — 당근을 **올린다**: 등록·목록 + 더미로 채우기 + **"두 명이 동시에 사면?"** 안 깨짐

**이 종이 보는 법**
- ⌨️ 직접 타이핑 / ✅ 눈으로 확인 / 🏷️ `[2-STEP-순번]` 찾아보기

> 💬 오늘도 **화면이 옆 사람과 달라도 정상.** 정답은 화면이 아니라 ✅ 확인 포인트.

## 🧭 오늘의 공정 (이게 오늘 가져가실 것)

```
PRD.md        무엇을 · 왜        ← 설계도 (한 장)
  ↓
plan.md       어떻게 · 어떤 순서로  ← 계획
checklist.md  어디까지 왔나        ← 진행표
  ↓
🚀 발사       AI가 완주
  ↓
검수          내 눈으로 확인
```

**좋은 명령엔 늘 세 가지가 있습니다 — 어디에 · 무엇을 · 어떤 재료로.** 하나라도 빠지면 그 자리를 AI가 대신 정합니다.

## STEP 0 · 폴더 열고 설계도 넣기

1. 바탕화면에 **`mini-carrot`** 폴더 (영문 소문자·하이픈)
2. Desktop → **`Code` 탭** → **`Select folder`**로 그 폴더 선택
3. 강사가 준 **PRD 파일**을 그 폴더에 **`PRD.md`**로 저장

**⌨️ `[2-0-1]` 킥오프**
```
폴더가 비어 있는지 확인하고, git으로 관리 시작해줘
```
> ✅ **확인:** "비어 있고, git 관리를 시작했다"는 답이 오면 성공.

---

## STEP 1 · 설계도 완성 — 빠진 조각 채우기

> 🎯 PRD ⑨번이 비어 있습니다. 수업에서 **여러분이 찾은 문제**를 요구사항 문장으로 박습니다.

**⌨️ `[2-1-1]` 요구사항 추가**
```
PRD.md의 ⑨ 추가 요구사항에 이 두 줄을 채워줘:
1. 구매는 여러 명이 동시에 눌러도 재고가 꼬이면 안 된다 (동시성을 고려해서 구현할 것)
2. 기술: Firestore를 쓴다. firebase 프로젝트에 연결해서 진행하되, 여의치 않으면 로컬 에뮬레이터로 진행해도 된다
그리고 ⑦ 성공 기준에 "재고 1개 상품에 두 명이 동시에 구매를 눌러도 딱 한 명만 사진다"를 추가해줘
```
> ✅ **확인:** `PRD.md`를 열어 **⑨에 두 줄, ⑦에 새 기준**이 들어가 있으면 성공. (설계도는 **내 눈으로** 검수)

**💬 이 명령을 뜯어보면**

| | 구절 | 뜻 |
|---|---|---|
| ① | `⑨ 추가 요구사항에 이 두 줄을 채워줘` | **어디에** — 파일 + 섹션 번호를 못 박았다 |
| ② | `재고가 꼬이면 안 된다 (동시성…)` | **무엇을** — 오늘 발견한 그 벽 |
| ③ | `Firestore… 여의치 않으면 로컬로` | **어떤 재료로 (+ 안 되면 어디로)** — 환경이 제각각이라 넣은 방어책 |

## STEP 2 · 진행표 만들기 (compass)

> 🎯 설계도는 "무엇을·왜"까지만 정합니다. **수학 문제와 같아요 — 답은 하나인데 푸는 길은 여러 개.** 그래서 **순서**까지 정해줍니다.

**⌨️ `[2-2-1]` 계획 · 진행표 생성**
```
PRD.md를 바탕으로 plan.md, checklist.md 만들어줘.
환경 셋업(firebase 프로젝트 생성·연결)부터 시작해줘
```
> ✅ **확인:** `plan.md`·`checklist.md`가 생기고, checklist가 **단계 5~7개**로 나뉘어 각 단계에 할 일이 체크박스로 달려 있으면 성공. **단계 수·이름은 사람마다 다릅니다.**

> 💬 **명령이 짧아도 되는 이유** — 설계도가 이미 다 말해줬으니까요. 문서를 챙기면, 명령이 가벼워집니다.

---

## STEP 3 · 🚀 한 방 발사

> 🎯 진행표만 잘 만들면, 명령은 이게 전부입니다. AI가 알아서 완주합니다.

**⌨️ `[2-3-1]` 발사**
```
checklist.md 순서대로 전부 진행해줘.
라이브러리 사용법이나 최신 문법이 필요하면 context7으로 확인하면서 진행해.
각 단계가 끝나면 그 단계의 완료 기준을 스스로 테스트해서, 통과를 확인한 뒤 다음 단계로 넘어가줘.
한 단계 끝날 때마다 커밋하고, 그 단계 이름으로 태그도 달아줘.
모든 구현이 끝나면 각 단계별로 뭘 했는지 한 줄씩 정리해서 보고하고,
로컬 서버로 띄워서 브라우저로 열어줘
```
> ✅ **확인:** 단계 1(셋업) 로그가 **흐르기 시작하면 정상.** 끝나길 기다리지 말고 설명을 들으세요.
> ⚠️ 권한 팝업이 뜨면 다같이 클릭 (1회차와 동일) · Firestore는 무료 Spark 플랜 — **카드 등록 없음.**

**💬 이 여섯 줄에 전부 들어 있어요**

| | 구절 | 뜻 |
|---|---|---|
| ① | `context7으로 확인` | 1회차 그 습관을 **명령에 박았다** |
| ② | `완료 기준을 스스로 테스트해서, 통과를 확인한 뒤` | **자체 게이트** — 에러를 안고 다음 단계로 못 넘어간다 |
| ③ | `커밋하고, 그 단계 이름으로 태그도` | 단계마다 **이름 붙은 세이브포인트** |
| ④ | `각 단계별로 뭘 했는지 한 줄씩 보고` | **몰아서 보고** — 자동 모드라 중간에 대답할 일이 없다 |

---

## STEP 4 · 검수 — "됐다"는 말을 믿지 않기

> 🎯 AI는 거짓말을 하지 않습니다. 다만 **자기 기준으로 통과**했다고 말할 뿐이에요.

**✅ 내 눈으로 확인할 것**
- [ ] 상품을 등록하면 목록에 **바로 뜬다**
- [ ] 더미 20개로 채우면 **진짜 게시판처럼** 보인다
- [ ] 구매를 누르면 **재고가 줄어든다**
- [ ] **재고 1개 상품**을 두 탭에서 동시에 구매 → **딱 한 명만** 사지고, 다른 쪽은 품절

## 🎁 오늘 손에 남은 것

- [ ] **PRD.md** — 한 장짜리 설계도 (외주 발주서로도 그대로 씁니다)
- [ ] **plan.md · checklist.md** — 계획과 진행표
- [ ] **단계별 커밋 + 태그** — 언제든 되돌아갈 세이브포인트
- [ ] **돌아가는 게시판** — 등록·목록·더미·동시구매
- [ ] **공정 그 자체** — 설계도 → 진행표 → 발사 → 검수. **오늘 제일 큰 수확입니다.**

## 🆘 막혔을 때 (실제로 터졌던 것들)

| 증상 | 그대로 치세요 |
|---|---|
| `firebase projects:create` 실패 — *display name contains invalid characters* | `프로젝트 이름을 영문으로 바꿔서 다시 만들어줘` (구글은 프로젝트 표시 이름에 **한글을 안 받습니다**) |
| `firebase projects:create` 실패 — *exceeded your allotted project quota* | `새로 만들지 말고, 내 기존 firebase 프로젝트에 연결해서 진행해줘. 없으면 로컬 에뮬레이터로 진행해줘` |
| 화면은 도는데 **Firebase 콘솔이 비어 있음** | `지금 Firestore가 실제 프로젝트야, 로컬 에뮬레이터야?` (로컬이면 껐다 켤 때 데이터가 사라집니다 — 알고만 계시면 OK) |
| 재고가 2씩 줄어듦 (동시성 버그) | `동시에 구매해도 재고가 1만 줄게 트랜잭션으로 다시 잡아줘` |
| 목록이 안 보임 | (브라우저 콘솔 에러 복사) `이거 떴는데 목록이 안 떠. 고쳐줘` |
| 응답이 끊기거나 세션이 이상함 | `PRD.md와 checklist.md 읽고, 체크 안 된 단계부터 이어서 진행해줘` (새 세션) |
| **토큰이 다 떨어짐** | 오늘 만든 **PRD·checklist·커밋**은 그대로 남습니다. 충전 후 위 문장 한 줄이면 이어집니다. |

## ✋ 진행 약속 (지난주 그대로)

1. **화면이 달라도 정상** — AI는 매번 조금씩 다르게 만듭니다. 옆 사람과 달라도 틀린 게 아니에요.
2. **정답은 화면이 아니라 ✅ 확인 포인트** — "여기까지 되면 OK"가 도착선입니다.
